### v0.22.0（2026-08-07）· 基础类型包装类（对标 Java 装箱/拆箱）

> **目标**：用户打开 `stdlib/src/lang/*.hao` 即可看到 Int/Bool/Double/String 的装箱拆箱条件与方法 API（解决「不知道 String 有哪些方法」）。
>
> **三种形态**（每个文件头注释写全）：
> 1. **内建值/串**：`Int`/`Bool`/`Double`/`String`（类型标注裸名永远是内建）。
> 2. **可空装箱** `T?`：仅值类型；编译器 `hao_box_*` / `hao_unbox_*`（与包装类无关）。
> 3. **对象包装**：`Integer`/`Boolean`/`lang.String`/`lang.Double`（显式 `valueOf`；可当 `Object`）。
>
> **当前无** Java 式隐式 `Int`↔`Integer` 自动装箱；需要 Object 时显式 `Integer.valueOf(n)`。

- **类名策略**：`Int`/`Bool` 包装为 `Integer`/`Boolean`（避免 `new Int` 被 resolve 成内建）。`String`/`Double` 与内建同名 → 类型标注写 `lang.String`/`lang.Double`，或靠 `valueOf` 推断；`new String(s)` 失败，用 `String.valueOf(s)`。
- **API**：Integer/Boolean/Double — `valueOf`/`parse`/`toStr`/`compare`/`intValue` 等 + 覆写 `hashCode/equals/toString`。String — 实例 `length/isEmpty/substring/indexOf/contains/startsWith/endsWith/charAt/trim/toUpperCase/toLowerCase`；静态 `valueOf/fromInt/fromDouble/fromBool/compare`。
- **运行时**：`runtime_string.c` 增补 substring/indexOf/trim/parse_* 等；`lang/native.hao` 集中 extern（防重复 declare）。
- **加载**：`DriverResolve` 隐式加载 `lang`；`IRGen` 隐式 `import lang.*`（同 object）。
- **限制**：类**静态方法不支持同名重载**；静态与实例**不能同名**（故静态转串叫 `toStr`，String 不以静态 `length(s)` 与实例 `length()` 并存）。
- **验收**：套件 **433** 行；`test/suite/langbox.hao` + `stdlib_extra.hao`。
- **本版补充（不升版本号）**：`hash` 独立包（迁出 collections）；`math`/`random`/`assert`/`text`；泛型实例化恢复 import。
- **文件**：`stdlib/src/lang/*`、`stdlib/src/hash/`、`math/`、`random/`、`assert/`、`text/`、`runtime_string.c`、`DriverResolve.cpp`、`IRGen.cpp`/`IRGenClass.cpp`、`VERSION` 仍 0.22.0。

### v0.21.1（2026-08-07）· 规约补齐 + Windows CRT 最小集 + 发行包可携

> **背景**：v0.21.0 只把 **net/ws2_32** 改成 dynload；gc/thread/time/print/dynload 仍 `#include <windows.h>` 产生 `__imp_*`。无 VS 机器上真正挡住「任意程序」链接的是 **libcmt 的 DEFAULTLIB**（`kernel32`/`libvcruntime`/`libucrt`），与 ws2_32 无关。另：本机有 `D:/buildLang/stdlib` 绝对路径兜底时，残缺发行包在本机仍能 `import net`，别人机器才报「找不到包」。
>
> **两层分开处理（架构，不是补丁）**：
> 1. **系统 API 层（5.12）**：全部走 `hao_dl_*` / `hao_win_*`，obj 无 `__imp_*`，directives 仅 `libcmt`。
> 2. **CRT 层**：MSVC 静态 CRT 链接期硬需求 → 按目标 arch 采集最小 `.lib` 集进 `lib/sysroot/win-<arch>/lib`，`DriverLink` 自动 `-L`。

- **dynload 引导**：`runtime_dynload.c` 经 TEB→PEB→LDR 找已映射的 `kernel32.dll`，解析导出得 `GetProcAddress`/`LoadLibraryA`/`FreeLibrary`（不链导入表）。x64 用 `__readgsqword(0x30)`；arm64 用 `x18`。
- **`runtime_winapi.c`（新）**：惰性绑定 CreateThread/Sleep/临界区/GetThreadContext/控制台/时间等；gc/thread/time/print 只调 `hao_win_*`。
- **CRT 最小集**：`libcmt` + `libvcruntime` + `libucrt` + `kernel32` + `oldnames` + `uuid`（约 57MB）。`uuid` 常被用户侧/`windows.h` DEFAULTLIB 拉入。**禁止**混放 x64/arm64。
- **发行包路径**：`stdlibSrcDir` / `findRuntimeLib` / `findWinCrtLibDir`——若检测到旁有自带 `lib/llvm/bin/clang.exe`（便携布局），**禁止**回退编译期 `HAO_STDLIB_DIR`/`HAO_ROOT_DIR`。找不到包时错误信息列出已搜索路径。

  | `win-arm64` | 同上 `-Target win-arm64`（需本机 VS ARM64 工具集） |

### v0.20.0（2026-08-07）· 注解 @interface + Action/Func + 反射 invoke + GC v2

> **目标**：四项一批做完——注解定义改 Java 风格 `@interface`、预置 C# 风格 `Action`/`Func` 泛型函数类型别名、反射通用方法 invoke、GC v2（stop-the-world 线程暂停 + 扫所有线程栈）解锁 worker 并发分配。GC v3（精确堆扫 + 分代 + 写屏障）经用户确认推迟到下一批。

- **注解定义改 `@interface`**：词法删 `ANNOTATION` token；`annotationDecl` 改 `AT INTERFACE IDENT LBRACE annotationMember* RBRACE`。`@`(AT) + `interface`(INTERFACE) 拼成注解声明，与注解使用 `@Name(args)`（annotationUse）消歧：`@` 后跟 `INTERFACE` 即声明、跟 IDENT 即使用。IRGen 只调 `decl->annotationDecl()`/`IDENT()`/`annotationMember()`，不触碰 ANNOTATION token，故语义逻辑零改动。
- **预置 `Action`/`Func`**：`resolveType`（IRGen.cpp）在 delegate 查找前内建识别 `Action`/`Func`（全局可用，对标 Object）：
  - `Action` = `()->Unit`；`Action<T1,...>` = `(T1,...)->Unit`。
  - `Func<...T, R>` = `(...T)->R`（最后一个类型实参是返回类型），`Func` 至少 1 参。
  - 用 `Type::makeFunc` 直接构造 Func 类型，零运行时开销。`delegate` 关键字与语法保留。
- **反射通用 invoke**：
  - `emitInvokeThunk`（IRGenClass.cpp）为每个本类声明的方法生成统一调用器 `define i64 @<irName>$invk(i64 %obj, ptr %argslots)`：从 argSlots 按序 load 每形参 8 字节槽，按形参真实 LLVM 类型转换（Int 直接用 i64 / Double bitcast / Bool trunc i32 / ref inttoptr ptr），虚方法经 this 虚表分派（保持多态）、static/非虚直接调 `mi.irName`，返回值统一转 i64。
  - `HaoMethodMeta` 加 `invoke`（ptr）字段；`emitClassMeta` 方法数组改为**实例方法 + 静态方法**都入元数据（v0.20.0 起静态方法也可反射）。
  - `runtime_reflect.c`：`find_method` 按方法名**走父类链**查找（继承方法可 invoke）；`hao_reflect_invoke` 调 thunk 返回 8 字节结果；`_str/_bool/_double/_void` 便捷包装 + `ptrtoint/inttoptr/dbl_bits/bits_dbl/bool_val/val_bool` 槽位转换助手。
  - `reflect.hao`：`Type.invoke(o,name,args:[Int]):Int`（原始 8 字节）+ `invokeStr/Bool/Double/Unit` + 顶层 `ptrOfStr/strOfInt/dblBits/bitsDbl`。
  - **坑**：内联 `getelementptr` 引用函数局部变量报 "invalid use of function-local name"——须先把 gep 当独立指令发射再 load。
- **GC v2（stop-the-world + 线程注册表 + 扫所有线程栈）**：
  - 每线程栈顶改 TLS（`g_stk_top`），不再全局 `gc_stack_top`。
  - 线程注册表 `gc_threads[GC_MAX_THREADS]` 记录每线程 os id + 栈顶；`gc_register_thread`/`gc_unregister_thread`（调用点：gc_init 主线程、runtime_thread.c 的 run_closure/pool_worker 入口/退出、gc_alloc 顶部安全性兜底）。
  - `gc_stop_the_world_scan`：Windows 用 `OpenThread`+`SuspendThread`+`GetThreadContext` 读 RSP 扫 `[RSP, stackTop)` 再 `ResumeThread`；Linux 用 `SIGUSR2` 信号停驻（Boehm 风格，处理器把自身 SP 记 TLS、自旋等 `g_park_release`），GC 等全部 park 后扫再统一释放。
  - 收集仍保守扫堆 + 保守扫各线程栈（无栈图也正确，绝不误回收）；关键是**不再只扫当前线程栈**，因此 worker 内分配对象不再被其他线程 GC 误回收。
  - **Linux 需 `#define _GNU_SOURCE`**（`pthread_getattr_np` 取线程栈顶）。
- **已验证**：`test/suite/v20.hao`（Action/Func、反射 invoke 含多态/继承/静态、GC 并发分配 4 线程各建大 List）；套件基线 **392 行**全绿（多次跑稳定）；Linux 交叉编译出静态 ELF。
- **文件**：`src/ast/HaoLangLexer.g4`(删 ANNOTATION)/`HaoLangParser.g4`(annotationDecl→AT INTERFACE)；`src/irgen/IRGen.cpp`(Action/Func)；`src/irgen/IRGenClass.cpp`(emitInvokeThunk/方法数组含静态/emitClassMeta struct 加 invoke)；`src/irgen/IRGen.h`(emitInvokeThunk 声明)；`stdlib/runtime_reflect.c`(invoke+find_method+转换助手)/`runtime_gc.c`(线程注册表+STW+每线程栈顶)/`runtime_thread.c`(注册/注销)/`runtime_internal.h`(gc_register_thread 声明)；`stdlib/src/reflect/reflect.hao`(invoke API)；`VERSION` 0.20.0。
