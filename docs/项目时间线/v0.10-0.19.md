### v0.18.0（2026-08-07）· 泛型接口 + for...in 迭代协议重做

> **目标**：实现 Java/C# 模型的泛型接口（`Iterable<T>`/`Iterator<T>`），泛型类可 `implements Iterable<T>`，并把 for...in 迭代协议从 v0.15.0 的 `toArray()` duck-typing 改为接口分派（`iterator()`/`hasNext()`/`next()`）。这是工作规则第 8 条"不能将就"的直接落地。

- **API**：`collections.Iterable<T>`（`iterator(): Iterator<T>`）、`collections.Iterator<T>`（`hasNext(): Bool` / `next(): T`）、`collections.ArrayIterator<T>`（基于数组的通用迭代器）。`List/Stack/Queue/Set` 改为 `: Iterable<T>` 并提供 `iterator()`。`toArray()` 保留（函数式 API 仍用，且作 genFor 向后兼容兜底）。用户自定义泛型接口/泛型类实现泛型接口均支持。
- **关键知识**：
  - **接口单态化镜像类单态化**：泛型接口声明=模板（`typeParams` 非空，不参与运行时）；`instantiateInterface` 复制模板 methods + `substType` 替换 T→实参，命名 `Iterable$Int`，幂等缓存于 `interfaces_`。
  - **槽位按模板共享**：接口方法虚表槽位只给模板分配一次（`assignVtableSlots` 跳过 `isGenericInstance()`），所有实例复制模板槽位 → 绕开"实例何时创建、槽位何时分配"的时序问题。
  - **管线重排**（IRGen.cpp generate()）：`resolveInterfaceImpls` 拆成 `assignVtableSlots`（分配槽位，先于实例化）+ `fillVtableEntries`（填表，后于全部泛型实例）。emitVTables/emitTypeIdLists 移到泛型实例循环之后。**泛型实例的字段槽位偏移必须在代码生成前**：非泛型类在 assignVtableSlots、泛型实例在 instantiateClass 末尾（`vtableShiftFields`），否则 ctor 按未偏移槽位写字段覆盖虚表指针→段错误。
  - **typeids 两遍**：`emitTypeIdLists` 在 genUnitTopLevel 前跑第 1 遍（is/as 编译期检查需要 typeIdLists_），泛型实例生成后跑第 2 遍（补 List$Int 等），加 `typeIdLists_.count` 幂等守卫防重复定义。
  - **连带实例化**：实例化接口时递归 `ensureInterfaceInstances` 实例化其方法签名中引用的泛型接口（如 `Iterable<T>.iterator()` 返回 `Iterator<T>`，实例化 `Iterable<Int>` 须连带 `Iterator<Int>`）。**坑**：必须在 `std::move(im)` 之前调用（move 后 returnType 已空）。
  - **3 处按实例名解析**：`isAssignable`（类→接口）、`applyMethodCall` 接口分派、`findCommonSupertype`，都用 `Type::makeInterface(name, args)->monoName()`（`Iterable<Int>`→`Iterable$Int`）而非裸名。
  - **genFor 三路径**：数组快路径 → 可迭代接口（检测含 `iterator(): Iterator<X>` 方法的接口，不依赖接口名硬编码）→ `toArray()` 兜底。可迭代循环体 `genForIterable` 经虚表分派调 `iterator()`/`hasNext()`/`next()`。
- **坑**（详见第 6 章）：`func main(): Int` 函数头被声明为 i32 而 return 发 i64（预存 bug，main 返回 Unit 未触发，本批绕开）；泛型类实现接口此前零覆盖，需重排管线。
- **已验证**：`test/suite/generic_iface.hao`（自定义泛型接口/泛型类实现/接口变量接收/for-in Iterable/多元素类型）；改 stdlib collections 后 `--rebuild-all` 套件 **363 行**全绿；Linux 交叉编译产出静态 ELF。
- **文件**：`SymbolTable.h`（InterfaceInfo 加泛型模板字段）；`IRGenClass.cpp`（注册存 typeParams、collectInterfaceMembers 放开泛型、instantiateInterface/ensureInterfaceInstances/instantiateAllGenericInterfaces 新函数、addBase 按实例名分流、resolveInterfaceImpls 拆分、vtableShiftFields）；`IRGen.cpp`（管线重排、isAssignable/findCommonSupertype 按实例名、typeids 两遍）；`IRGenExpr.cpp`（applyMethodCall 接口按实例名）；`IRGenControl.cpp`（genFor 迭代协议重做）；`Type.h`（makeInterface 带 args 重载）；`stdlib/src/collections/Iterable.hao`（新）+ List/Stack/Queue/Set 改实现 Iterable。

### v0.19.0（2026-08-07）· 委托 / 注解 / 反射 / 时间 / 线程 / main args

> **目标**：六个特性一批做完统一升版——委托（C# 风格命名函数类型 + 方法组转换）、注解 + 反射（Java 模型）、time 时间包、thread 线程/线程池、main 命令行参数、修复预存 main 返回类型 bug。

- **委托 Delegate**：
  - 语法 `delegate (Int)->Int IntOp;`（`topLevelDecl` 加 `delegateDecl`，lexer 加 `DELEGATE`）。是**函数类型别名**（编译期概念，零运行时开销），`resolveType` 命中 `delegates_` 表返回对应 Func 类型。
  - **方法组转换** `obj.method`：`applyMemberAccess` 方法名分支生成绑定 this 的闭包 env（槽0=包装器、槽1=this）。`ensureMethodWrapper` 生成 `define ret @Class.method$wf(ptr %env.arg, args...)`，从 env 槽1 取 this，虚方法经虚表分派（保持多态）、非虚静态调用。缓存于 `methodWrappers_`。
  - 复用已有函数类型/lambda/顶层函数当值（`@foo$wf`）机制。
- **注解 Annotation**：
  - 定义 `annotation Name { val field: T; }`（lexer `ANNOTATION`，parser `annotationDecl`），使用 `@Name(args)`（`annotationUse`，复用 `@`/AT）标记类/方法/字段前。
  - 注解类型登记为类（`isAnnotation=true`），字段收集进 `ci->fields`；`genUnitTopLevel` 对 annotationDecl 静默跳过（不生成代码）。
  - 注解使用存 `ClassInfo/MethodInfo/FieldInfo.annotations`（`AnnotationUse{name, args{键,值}}`），参数编译期常量字符串化（`resolveAnnotationUses`/`annotationArgValue` DFS 取字面量）。
- **反射 Reflection**：
  - 编译器为每个类生成 `HaoClassMeta`（`emitClassMeta`）：类名/父类/接口/字段/方法/注解 + 该类的虚表指针。全 8 字节字段的 C 结构体（`runtime_reflect.c`），与 LLVM IR struct 布局一致（同一目标 ABI，零对齐差异）。注册进 `@hao_all_metas`（NULL 结尾）。
  - `reflect.typeOf(o)`（reflect 包）经 `hao_reflect_getclass(o)` 读对象槽位0 虚表指针，线性遍历 metas 反查类元数据。**meta 指针存 `Int?`（底层即指针，原样跨 C 边界传递，不拆箱）**。
  - Type 自省：name/superclass/interfaces/isAbstract/isEnum/fields/methods/annotations；字段值 `getField(obj,name):String?` 与 `setField(obj,name,value)`（Int/Double/Bool/String 以字符串跨边界传递）。
  - **限制**：运行时方法 invoke 与运行时动态定义类/属性/方法需解释器/VM 子系统，列为后续（"不能将就"）。
- **time 时间包**：`runtime_time.c`（当前纳秒 Windows `GetSystemTimePreciseAsFileTime`/Linux `clock_gettime`；时区偏移 localtime/gmtime 差值；按偏移用 gmtime 取字段/格式化）。`time.Time` 存 `ts`（Unix 纳秒）+ `offset`（相对 UTC 秒偏移，用 **Int** 非 Int?——数值无需装箱）。`format("yyyy-MM-dd HH:mm:ss.SSS")` 支持 yyyy/MM/dd/HH/mm/ss/SSS 占位符。`now()` 本地 / `nowUtc()` UTC。
- **thread 线程/线程池**：`runtime_thread.c` 跨平台（Windows CreateThread/ConditionVariable，Linux pthread）。线程运行 HaoLang 闭包 env（槽0=fnptr）。`Thread.start/join`、`sleep`/`sleepNanos`/`yield`、`newPool(n)`/`submit`/`shutdown`。
  - **GC 线程安全**（关键）：`runtime_gc.c` 加互斥锁（Windows CRITICAL_SECTION/Linux pthread_mutex，**非递归锁 + 持锁内直接调 trampoline** 避免嵌套死锁）；加**外部 GC 根**（`hao_gc_add_root/remove_root`，`gc_collect_inner` 标记时一并扫描）——线程闭包 env 注册为根保活（否则主线程提交后不再引用 env，被回收 → worker 崩溃）。
  - **局限**：保守扫描只扫当前线程栈，worker 线程内分配 GC 对象仍可能被其他线程触发的 GC 误回收；worker 内应避免分配（用 sync 原子等无分配操作）。待 GC v2（线程暂停 + 精确扫描）解决。
- **main 命令行参数**：`func main(args: [String])` → C 入口签名 `define i32 @main(i32 %argc, i8** %argv)`（`genFunction` 检测 main 唯一参数为 `[String]` 时 `hasArgs`），`@hao_make_args`（`runtime_string.c`）从 argc/argv 构造 `[String]` 数组（**跳过 argv[0] 程序名**，对齐 Java/C#），存 `mainArgsIR_` 供参数绑定。`hao run a.hao -- p1 p2`：main.cpp 遇 `--` 后参数收集进 `opts.programArgs`，`Driver::run` 拼到用户程序命令行。
- **main 返回类型 bug 修复**：`genReturn`/`emitUnwindRet` 在 `inMain_` 且返回 `Int`(i64) 时 `trunc i64 to i32` 再 `ret i32`；`genFunction` 校验 main 返回类型只能是 Unit 或 Int。
- **vtable 哨兵（顺带修潜在 bug）**：`emitVTables` 每个 vtable 数组末尾追加 `ptr @<cls>.meta` 哨兵。作用：① 内容相同的 vtable 是 `private constant`，链接器会合并导致地址不唯一（反射 getClass 误判类，is/as 也有同类隐患），哨兵使每类 vtable 唯一；② 运行时可经虚表反查类元数据。
- **坑**：`Int?` 是装箱块指针，不能直接存数值（time 用 Int）；extern 返回 `Int?` 时 C 应返回块指针否则 HaoLang 当指针存；lambda 捕获分析要把包名（fmt/import 别名）排除，否则 `{ fmt.println(...) }` 报"捕获 undefined fmt"（`collectFreeNames` 加 isPkg 检查）。
- **已验证**：`test/suite/v19.hao`（delegate 15/11、reflect V19Person/自省/字段 30→99、time 年份/格式、thread 用 sync 原子计数 1/4）；套件基线 **376 行**全绿（多次跑稳定）；Linux 交叉编译产出静态 ELF。
- **文件**：`src/ast/HaoLangLexer.g4`(+DELEGATE/ANNOTATION) + `HaoLangParser.g4`(delegateDecl/annotationDecl/annotationUse)；`SymbolTable.h`(AnnotationUse/annotations/isAnnotation)；`IRGen.cpp`(collectDelegates/resolveType 拦截/collectClassMembers 注解收集/emitClassMeta 调用/resolveAnnotationUses/annotationArgValue)；`IRGenClass.cpp`(annotationDecl 登记/字段收集/emitClassMeta)；`IRGenLambda.cpp`(ensureMethodWrapper/方法组转换)；`IRGenExpr.cpp`(applyMemberAccess 方法组转换/collectFreeNames isPkg)；`IRGenExcept.cpp`(main Int→i32 trunc)；`IRGen.h`(delegates_/methodWrappers_/mainArgsIR_/emitClassMeta)；`runtime_reflect.c`(新)/`runtime_time.c`(新)/`runtime_thread.c`(新)/`runtime_gc.c`(锁+外部根)/`runtime_string.c`(hao_make_args)/`runtime_internal.h`(数组宏/GC根声明)；`stdlib/src/reflect/`(新)/`time/`(新)/`thread/`(新)；`main.cpp`(`--` 分隔)/`Driver.cpp`(programArgs)/`Driver.h`(programArgs)；`VERSION` 0.19.0。

### v0.17.0（2026-08-06）· OOP 类体系补全

> **目标**：补齐面向对象类体系——static 成员/静态构造器、extends/implements 关键字、super 构造链、枚举类、Go 式 init()。六个特性一批做完统一升版。

- **API**：
  - **static 成员**：`static var/val X: T`、`static func f()`；`ClassName.X`/`ClassName.f()` 访问（实例对象访问静态成员亦可）。静态字段是类级全局变量，不占对象槽位/虚表/继承；静态方法无隐式 this。
  - **extends/implements**：`class Dog extends Animal implements Shape_{}` 显式区分；旧 `class Dog : Animal, Shape` 仍兼容。
  - **super 构造链**：构造器内 `super(实参)` 调父类构造，支持多级。
  - **静态构造器**：`static ClassName() { }`，类首次被引用（访问静态成员/首次 new）前执行一次。
  - **枚举类**：`enum Color { RED, GREEN }` 编译成类，常量是静态实例，提供 name()/ordinal()/toString()。
  - **Go 式 init()**：包级 `func init()`，main() 前按依赖顺序自动执行。
- **关键知识**：
  - **static 字段** = 类级全局 `@Class.X = global <type> <常量>`；`emitStaticFieldGlobals` 常量写全局、非常量零值+合成进静态构造器。访问经 `genPrimary` 类名返回 `Value("", makeClass)`（静态接收者），`applyMemberAccess/applyMethodCall/genAssign` 加静态分支；`base.ir.empty()`（类名）访问实例成员报"静态上下文不能访问实例成员"。
  - **静态构造器**：`genStaticConstructor` 生成三符号 `@Class.initguard`（0未开始/1进行中/2完成）+ `@Class.staticinit`（非常量静态字段初始化 + 静态构造器体）+ `@Class.ensureInit`（guard==0 才跑）。访问点调 `emitStaticEnsureInit`（静态字段读/写、静态方法、new 共 4 处）。**防递归**：guard 在调 staticinit 前置 1。
  - **enum**：`registerClassNames` 登记为类（`isEnum=true`）；`collectClassMembers` 合成 `_name`/`_ordinal` 字段、私有构造器、name()/ordinal()/toString() 方法、每常量一个静态字段、`staticCtorNode=enumDecl`；`genEnum` 手工发射构造器/方法；`genStaticConstructor` isEnum 分支创建实例。`new Color()` 拒绝。
  - **init()**：`collectFunctionSignatures` 识别顶层 `func init()` 记录 irName；`generate()` 收集后 `std::reverse(initCalls_)`（依赖在前）；`genFunction` 生成 main 时 entry 后先 call 各 init。**每包一个 init**。
- **坑**（详见第 6 章）：多个同签名 init 让 genFunction 重载匹配全落第一个 → 限制每包一个；enum 常量须逗号分隔；静态字段非常量初始化报错改合成进静态构造器。
- **已验证**：static(15)/extends_impl(12)/super_ctor(10)/static_ctor(7)/enum(15)/init_func(2) 单文件 + initpkg 跨包 init 顺序；基线 **426 行**全绿；Linux 交叉编译出静态 ELF。
- **文件改动**：语法 `HaoLangLexer.g4`(+EXTENDS/IMPLEMENTS/ENUM) + `HaoLangParser.g4`(classBase/staticCtorDecl/enumDecl)；`SymbolTable.h`(isStatic/staticFields/staticMethods/staticCtorNode/hasStaticInit/isEnum/initCalls_)；`IRGenClass.cpp`(收集/genStaticConstructor/genEnum/emitStaticFieldGlobals)；`IRGenExpr.cpp`(static 访问/赋值、super(args)、new 拒 enum)；`IRGen.cpp`(findCommonSupertype 修 Object、init() 收集与 main 调用)。

### v0.16.0（2026-08-06）· Object 根父类 + 集合 key 重做

> **目标**：实现 Java/C# 模型的 `Object` 根父类——所有类默认继承 Object，提供默认 `hashCode()`/`equals()`/`toString()`（身份语义，可覆写）；并把集合 key 从 v0.15.0 的 `Hashable` 接口改为 Object 协议。这是反射特性的前置基础。

- **API**：
  - `object.Object`（编译器隐式加载 + 通配导入，无需 `import`）：`hashCode():Int`（身份哈希=对象地址）/ `equals(o:Object):Bool`（身份相等=指针相等）/ `toString():String`（`<0x地址>`，可覆写）。
  - **所有类默认继承 Object**：`class Person {}` 即隐式 `class Person : Object`；`is/as Object`、`Object` 类型接收任意对象均成立。
  - **集合 key**：`Map/Set` 的 key 支持 Int/Double/Bool/String + **任何对象**（默认按身份；覆写 `hashCode()`/`equals()` 后按内容）。不再需要 `Hashable` 接口。
- **关键知识**：
  - **Object 是真实 `.hao` 类**（`stdlib/src/object/Object.hao`），方法调 runtime C（`runtime_object.c` 的 `hao_object_hashCode/equals/toString`）。不特殊合成，走正常类/虚表机制。
  - **隐式加载 + 通配导入**复刻 fmt 机制：`DriverResolve.cpp` 自动 `loadPackageDir(object)`；`parseImports` 注入 `import object.*`，使裸名 `Object` 在所有包（含 stdlib 包）解析为 `object$Object`。**坑**：注入判断必须查「已存在 object 通配导入」，若用户只写了限定 `import object;` 也要补通配，否则裸名 Object 不解析。
  - **默认继承**两处：`collectClassMembers`（非泛型，跳过 `object$Object` 自身）+ `instantiateClass`（泛型实例）——`baseName` 为空时设为 `object$Object`。
  - **key 重做**：删掉 `Hashable` 接口，`Hash.hao` 的 `hashOf(Hashable)`→`hashOf(x:Object)`、`equalsKey(Hashable,Hashable)`→`equalsKey(Object,Object)`（内部调 `x.hashCode()`/`a.equals(b)`）。因所有类继承 Object，`isAssignable(Foo,Object)`=true，任何对象 key 都命中 Object 重载；String 等原始类型不可赋给 Object，不与专有重载冲突。
  - **Object 方法进虚表**：Object 有子类（=所有类），其 hashCode/equals/toString 经「参与继承的虚方法」分配共享槽位；`emitTypeIdLists` 使 Object 的 typeids = 所有类虚表，`x is Object` 运行时成立。
- **已验证**：`test/object_root.hao`（6 行：is/as Object、多态覆写 equals/toString/hashCode、身份语义）；`test/objectkey.hao` 重写为 Object 协议（8 行）。全量 426 行全绿；Linux 交叉编译产出静态 ELF。
- **文件**：`stdlib/src/object/Object.hao`（新）+ `runtime_object.c`（+3 函数）；编译器改 `DriverResolve.cpp`（加载）、`IRGen.cpp`（通配注入）、`IRGenClass.cpp`（默认继承）；`Hash.hao` 删 Hashable。

### v0.15.0（2026-08-06）· 集合库扩充

> **目标**：补齐集合库三件套——`Stack<T>`、`for...in` 迭代协议、对象 key 的 hashCode/equals 协议。

- **API**：
  - `collections.Stack<T>`：`push(x)` / `pop():T?`（空栈 null）/ `peek():T?` / `isEmpty():Bool` / `size():Int` / `toArray():[T]`。基于 `List<T>`，O(1)。
  - **for...in 迭代协议**：`for (x in it)` 现在支持任意含 **`public toArray(): [T]`** 方法的类（List/Stack/Set/Queue 均已实现），不再局限于数组。
  - **对象 key**：`Map/Set` 的 key 现在可以是任何**实现 `collections.Hashable` 接口**的对象（提供 `hashCode():Int` + `equals(o:Hashable):Bool`），按内容相等/内容哈希命中。
- **关键知识**：
  - **for...in 协议靠编译器 duck-typing，不引入泛型接口**（泛型接口当前不支持，见 probe 结论）。`IRGen::genFor` 对非数组序列：若是类且含 public `toArray():[T]` 方法，则调用它（有虚表槽位走虚表分派，否则静态调用，对齐 `applyMethodCall` 类方法分支）得到数组，再复用原数组迭代快路径。方法签名固定 `ret(ptr recv)`，返回 `ptr`。
  - **对象 key 复用顶层重载分派机制**（第 5.10 节）：`Hashable` 是非泛型接口，`Hash.hao` 新增 `hashOf(x:Hashable)=x.hashCode()` 与 `equalsKey(a:Hashable,b:Hashable)=a.equals(b)` 两个顶层重载。Map<K,V> 单态化后 K=Foo，`hashOf(key)` 经 `isAssignable(Foo,Hashable)`（IRGen.cpp:515，类实现接口即 true）选中 Hashable 重载，再经接口虚表分派调 `Foo.hashCode()`。与 Int/Double/Bool/String 重载无冲突（String 非类，不可赋给 Hashable）。
  - **用户自定义类作 key**：`class Foo : collections.Hashable` + `override hashCode()`/`equals(o)`，可在 `equals` 里 `o as Foo` 强转后按字段比较。
- **已验证**：`test/stack.hao`（9 行）、`test/foreach_collection.hao`（4 行，List/Stack/Queue/Set 迭代）、`test/objectkey.hao`（8 行，Map/Set 内容相等命中/未命中/remove）。全量 359 行全绿；Linux 交叉编译产出静态 ELF。编译器改动仅 `IRGenControl.cpp`（genFor + 协议），零运行时 C 改动。

### v0.14.0（2026-08-06）· 网络库 net

> **目标**：第三个系统库，TCP/UDP socket，跨平台（Windows Winsock / Linux BSD）。这是 haoroutine 与 Web demo 的网络基础。

- **API**：
  - `net.Socket`：`connect(host,port):Bool` / `send(data):Int`（返回发送字节数，失败/关闭 -1）/ `recv(maxLen):String?`（连接关闭/错误 null）/ `close()`。
  - `net.ServerSocket`：`listen(port):Bool`（绑定通配地址）/ `accept(client:Socket):Bool`（阻塞接受写入 client）/ `close()`。
  - `net.UdpSocket`：`open():Bool` / `bind(port):Bool` / `sendTo(host,port,data):Int` / `recvFrom(maxLen):String?` / `close()`。
- **关键知识**：
  - socket 句柄**复用 `Int?` 装箱单元**（8 字节 GC 块）存储：方法传 `this.fd` 给 C，C 侧当 `int64_t*` 读写句柄。与 sync 锁内存同一机制，零新增数据结构。

  - 单线程测试顺序绕过 accept 阻塞：**先 listen → 客户端 connect（进 backlog）→ 再 accept**；UDP 用 bind 后 sendto 自己**自发自收**。

### v0.13.0（2026-08-06）· 并发原语库 sync

> **目标**：第二个系统库，互斥锁 + 原子整数操作，跨平台。这是 `haoroutine` 并发与 `net` 的基础。

- **API**：
  - `sync.Mutex` 类：`lock()` / `unlock()`（原子自旋锁）。
  - 原子函数（作用于 8 字节 `Int?` 计数单元）：`atomicAdd(p,delta):Int`（返回加后）、`atomicFetchAdd(p,delta):Int`（返回加前旧值）、`atomicExchange(p,value):Int`（返回旧值）、`atomicCompareExchange(p,expected,desired):Bool`。
- **关键知识**：
  - 锁/计数单元**复用 `Int?` 装箱**（8 字节 GC 块，值类型装箱为指针）：HaoLang 侧 `var c: Int? = null; c = 0;` 或 `Mutex` 构造器 `this.state = 0;` 得到一个 8 字节 i64 单元，C 侧当 `int64_t*` 原子内存操作。零额外分配、零新增数据结构。
  - GC non-moving 指针稳定；锁状态值 0/1 是安全小整数，保守扫描读到不在堆区间 `[heap_lo,heap_hi)`，不会误判指针。
  - C 用 clang/GCC `__atomic_*` 内建（`compare_exchange_n`/`store_n`/`add_fetch`/`fetch_add`/`exchange_n`），MSVC 编译也走 clang，**无系统依赖、无平台分支**。
  - **坑**：`__atomic_compare_exchange_n` 的 expected 参数**就地更新为当前值**，自旋锁每次失败后必须重置回 0 再重试，否则死循环。
  - `Mutex` 方法内调包内私有 extern `_lock/_unlock`（`= "hao_sync_lock"`，irName 不带包前缀，直接 `call @hao_sync_lock`）——extern 在方法体内被调用的先例。
  - 编译器零改动（extern + 常规类/方法机制已就绪）；`build_runtime.ps1` 自动发现 `runtime_sync.c`。
- **已验证**：`test/sync.hao`（9 行）全对；Linux 交叉编译产出静态 ELF（`7f 45 4c 46`）。真并发互斥测试待 haoroutine/OS 线程就绪后补。
- **文件**：`stdlib/src/sync/sync.hao` + `stdlib/runtime_sync.c`。

### v0.12.0（2026-08-06）· 系统库 os

  - `readFile`：`fopen rb` → `fseek/ftell` 得大小 → `gc_alloc(size+1)` → `fread`。
  - 全部用 C 标准库（fopen/fread/fwrite/getenv/system/remove），MSVC 与 musl 都有，跨平台零适配。
  - 编译器零改动；`build_runtime.ps1` 自动发现 `runtime_os.c`。
- **已验证**：`test/os.hao`（9 行）：写中文文件读回正确（UTF-8）→ exists → getenv → remove 无残留；`system("exit 5")`=5。
