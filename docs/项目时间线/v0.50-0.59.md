### v0.55.3（2026-08-09）· while 局部提升 · 修 shadow 假活

> **目标**：v0.55.2 后 `liveBytes`/`remset` 已正常，但 monitor `blockCount` 仍随 warmup 台阶涨——根因是 IR 精确根泄漏，不是 sweep。

- **根因**：`while { var junk = ... }` 每轮 `root_push` 新槽，无限循环从不 `root_unwind` → 历史 List 对 GC **真可达**。
- **修复**：`genWhile` 提升体内 varDecls（跳过 lambda 体）；每轮只 store；循环结束 GC 槽置 null。
- **测试**：`gc_loop_var_root_smoke`（同型 40×2000，collect 后块数 < 15000）。
- **文档**：契约 §4.3；坑债 **BX**。勿把「排期 concurrent sweep」写成假活借口。

**验收**：套件 **1011**；loop/remset/根 smoke；`hao version`=0.55.3。

> **目标**：修 warmup 晋升后 major 仍把历史 junk 标活（`liveBytes≈heapBytes`）——根因是 remset 语义，不是「GC 不懂可达性」。

- **P0**：`gc_seed_roots_and_remset` — major **禁止** enqueue remset；仅 minor 对 remset 容器 `scan_precise`。
- **P1**：minor 后去掉对所有晋升对象的盲目 `gc_remset_add`（屏障记真实 old→young）。
- **观测**：`hao_gc_stats`/`GC.remsetCount()`；08-gc-monitor 面板一行。
- **测试**：`gc_remset_major_smoke`；原有 GC smoke 不回归。
- **文档**：契约 R2（remset 不是根）；坑债 **BW**。

**验收**：套件 **1011**；上述 smoke；`hao version`=0.55.2。用户须 rebuild runtime + 重启 monitor。
