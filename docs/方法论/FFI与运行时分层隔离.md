## 0\. 前置核心设计哲学（全文总纲）

**去C化、最小C底座、强边界隔离、GC绝对可控、自举友好、可调试可收口**

核心一句话：

**所有业务语义、对象生命周期、错误体系、容器字符串、资源管理全部交给 HaoLang；C/原生层只保留“硬件级、系统级、无法替代的最小底座”。**

本文档所有示例代码、接口名称仅为方法论示范，实际实现可自由调整，**约束规则、分层原则、禁止项为强制标准**。

## 1\. 三层强制分层架构（FFI \+ 运行时唯一合法模型）

从底层到上层严格分为三层，层与层**禁止跨层穿透、禁止逻辑下沉、禁止裸指针泄露**。

### 1\.1 底层：最小C运行时底座（不可再删层）

只保留**操作系统、LLVM、硬件调度**无法用高级语言实现的原语：

- GC 底层内存页分配、堆初始化、内存对齐

- GC 写屏障底层指令、安全点 poll、栈根扫描底层

- 线程/协程底层上下文切换、系统信号捕获

- 最小 FFI 跳板调用（纯参数转发，无业务逻辑）

- 程序启动/退出底层钩子、崩溃现场极简捕获

**强制约束：C 层绝对禁止实现任何业务逻辑**

禁止：字符串处理、容器、IO 封装、错误组装、日志、路径处理、资源管理、格式化。

### 1\.2 中间层：FFI 隔离桥接层（核心隔离层）

职责：**切断 C 世界与 HaoLang 世界的内存与类型污染**

所有跨语言交互必须经过此层，作用：

- 原生裸指针 → 统一封装为 HaoLang GC 托管句柄

- C 错误码 → 转换为 HaoLang 异常/Error 对象

- C 基础类型 → 转换为 HaoLang 原生类型（String/Int/数组）

- 禁止原生指针、C 结构体、C 字符串直接暴露到上层

- 统一 FFI 调用前后 GC 根状态、安全点状态维护

这一层是**全局唯一收口**，所有 FFI 行为统一规则、统一埋点、统一校验。

### 1\.3 上层：HaoLang 原生标准库（全业务层）

所有可高级语言实现的功能**100% 上移到 HaoLang**：

- 字符串、编码、格式化

- 数组、List、Map、集合容器

- 文件、IO、网络、路径封装

- 异常体系、错误堆栈、诊断信息组装

- 日志、Trace、Metrics、Debug 埋点

- 资源生命周期管理、缓存、池化

目标：**自举后，99% 标准库都是纯 HaoLang 代码**，无业务 C 依赖。

## 2\. 核心隔离方法论（FFI 最关键四条铁律）

### 2\.1 裸指针绝对隔离原则

**原生 C 指针禁止出 FFI 桥接层**

所有系统资源、C 结构体、外部库指针：

统一封装为：**GC 托管句柄对象（NativeHandle）**

规则：

- 句柄是 HaoLang 堆对象，参与 GC 根扫描

- 句柄内部持有原生裸指针（仅桥接层可访问）

- 句柄绑定 Finalizer，GC 回收时自动释放原生资源

- 上层用户代码永远看不到、碰不到裸指针

### 2\.2 类型完全映射原则（杜绝跨类型污染）

C 类型只做中转，**绝不作为上层 API 类型**

强制映射规则：

- C 数字 → HaoLang 原生值类型

- C 字符串 → **立即拷贝**为 HaoLang String（入桥）；出桥调 libc 前再 **`hao_ffi_dup_*` 拷贝到 C malloc**（属 C，调用方 free）

- C 数组 → 转换为 HaoLang 切片/数组对象（或桥内字节拷贝）

- C 结构体 / 资源指针 → **仅** `NativeHandle` 代理（Handle 代理释放，不接管 C 分配器）

- C 指针 → 禁止传出业务层；禁止以 `Long?` 藏 FILE*/socket/regex 等资源针

核心：**C 内存是临时内存，HaoLang 内存是托管长期内存**，两者不共享、不混用、不互相引用。**禁止**把 GC 堆内指针长期借出给 C。

### 2\.3 错误体系上层统一原则

**C 层只产出错误码，不处理错误、不组装堆栈、不输出日志**

所有错误语义、诊断信息、源码行号、堆栈溯源：

全部由 **HaoLang 上层统一收口**

收益：

- Debug/Release 错误体验一致

- 所有异常可映射源码位置

- 自举后错误体系完全不用重构

### 2\.4 GC 状态绝对稳定原则（FFI 最高优先级约束）

任何 FFI 调用必须保证：

- 进入原生代码前：临时根刷完、安全点状态固化

- 原生代码内部**禁止触发 GC**（无安全点）

- 退出原生代码后：恢复 GC 可扫描状态

- 原生回调进入 HaoLang 时，自动补全根作用域、句柄作用域

核心：**FFI 边界是 GC 状态的硬隔离线**。

## 3\. 运行时「去C化」完整方法论

### 3\.1 能上移必上移

只要能用 HaoLang 实现的逻辑，绝不放在 C 运行时：

- 字符串操作、编码转换、模板插值

- 所有容器逻辑、迭代、扩容、遍历

- 路径、文件解析、格式处理

- 日志、Trace、Metrics、诊断输出

- 异常封装、错误提示、崩溃信息组装

- 资源池、缓存、超时、重试逻辑

### 3\.2 C 层只留「不可替代底座」

未来自举完成后，C 运行时仅保留：

- GC 内存底层原语

- 安全点 \& 栈扫描底层

- 线程/协程上下文切换

- 极简 FFI 跳板

- 系统信号与最小崩溃捕获

实现：**极小内核 C 底座 \+ 100% 高级语言业务体系**

## 4\. 句柄系统完整规范（FFI 资源唯一托管方案）

### 4\.1 句柄分类

- **局部句柄**：单次 FFI 调用生命周期，函数退出自动销毁

- **全局句柄**：跨线程、跨调用长期持有，手动释放 \+ GC 兜底

### 4\.2 句柄强制规则

- 所有原生资源必须句柄化，禁止裸持有指针

- 句柄是 GC 引用类型，参与根枚举

- 句柄失效后禁止二次使用，上层做状态校验

- 句柄泄漏可被 Metrics 统计、可诊断溯源

- GC 移动、重排、标记阶段，句柄稳定性不受影响

## 5\. FFI 统一收口规范（和你 Debug 收口体系对齐）

完全遵循项目全局「统一收口原则」：

- 所有 FFI 调用统一入口，不散落各处

- 所有句柄创建/销毁统一入口

- 所有 FFI 错误转换统一入口

- 所有 FFI 埋点、Trace、统计收敛在入口内部

- 开关、调试、断言、日志全部收口，业务代码无散落 debug 逻辑

## 6\. 全套禁止性规则（FFI\+运行时红线）

❌ 禁止裸 C 指针暴露到 HaoLang 业务层

❌ 禁止用 `Long?` / `int64_t*` unit 藏 FILE* / socket / 正则引擎等 **C 资源**（须 `NativeHandle`）

❌ 禁止把 `hao_str_cstr`/`hao_str_data` 当作对外合法「借堆内指针给 C」模式（桥私有审计路径除外）

❌ 禁止 C 层实现业务逻辑、字符串、容器、IO 封装

❌ 禁止跨层直接访问底层内存，必须经过桥接层

❌ 禁止原生代码长期裸持有 GC 对象指针

❌ 禁止 FFI 调用过程破坏 GC 根状态、临时根状态

❌ 禁止 C 层直接输出日志、诊断、错误信息

❌ 禁止 C 结构体、C 字符串直接作为上层返回值

❌ 禁止业务层手动 free / 手动操作原生资源内存

## 7\. 顶层最终方法论（可作为文档结尾金句）

**底层留最小C底座、中间做强制FFI隔离、上层全原生HaoLang实现；**

**原生资源句柄托管、类型严格映射、GC状态绝对稳定；**

**错误诊断上层收口、调试埋点统一入口、一切可管控、可自举、可迭代。**
