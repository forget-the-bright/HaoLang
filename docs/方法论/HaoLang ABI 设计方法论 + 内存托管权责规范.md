# HaoLang ABI 设计方法论 + 内存托管权责规范
## 0 核心总纲
**ABI = 二进制通信协议，只规定「长什么样、怎么传、怎么调用」；
内存托管权独立于ABI，由「分配方持有生命周期责任」。
ABI兼容 ≠ 归属对方运行时。**

分层两条主线严格分开：
1. ABI层：定义跨边界二进制格式、对齐、调用约定；
2. 托管层：明确**哪一侧分配、哪一侧释放、谁拥有内存所有权**。
结合你已有的《FFI与运行时分层隔离规范》配套使用。

> **落地（v0.55.61）**：边界仅 **拷贝语义 | NativeHandle 代理**；fs/net/regex 已切 Handle；出桥 libc 经 `hao_ffi_dup_*`。索引见 [`README.md`](README.md)。

## 1 基础概念厘清
### ABI包含什么
- 基础类型内存布局、大小、对齐
- 函数调用约定（参数放寄存器/栈、返回值传递方式）
- 结构体排布、位域、填充规则
- 符号命名规则
只解决：**二进制数据双方能读懂**。

### 托管权判定黄金法则
> **谁调用分配接口（malloc / GC堆分配），谁拥有这块内存，谁负责释放。**
- HaoLang GC堆分配 → HaoLang托管
- C `malloc` /系统调用分配 → C原生内存
二者内存池相互独立，默认不共享所有权。

## 2 分类：数据类型 ABI策略 + 托管方案
### 类别1：基础值类型 i32/u64/f64/bool
1. ABI设计
    布局严格对齐平台C ABI，实现FFI直接传参；
2. 内存位置：HaoLang调用栈，无堆分配；
3. 托管归属：**HaoLang运行时**；
4. FFI规则：
    直接二进制拷贝传递；不存在所有权转移；
    C拿到的只是临时副本，不能修改影响上层原始变量；
5. 禁止：不要把简单值类型包装成句柄，过度设计。

> 类比Java int，栈上数值，JNI直接拷贝入C函数。

### 类别2：HaoLang GC引用类型（String、Array、GC结构体）
1. ABI设计
    内部存储字节/字段布局可以对齐C ABI格式（方便拷贝）；
    ⚠️**对外禁止直接暴露对象内部指针作为FFI参数**；
2. 内存位置：HaoLang GC堆；
3. 托管归属：**HaoLang GC全权托管**；
4. FFI可行方案二选一（桥接层统一处理）
    - 短期调用：拷贝一份数据到C临时堆，调用结束立刻free副本；
    - 不可行方案：长期把GC堆指针交给C保存（GC压缩/移动后指针失效，致命bug）；
5. 关键约束：
    GC对象本身不能直接作为C侧长期操作对象；ABI只是用来**拷贝数据**，不是共享内存。

> 对标Java byte[]：JNI推荐使用GetByteArrayRegion拷贝，不长期持有堆指针。

### 类别3：C原生资源（FILE*、socket、外部库结构体、malloc内存）
1. ABI设计
    原生指针遵循平台指针ABI；
2. 内存位置：C堆 / 操作系统内核资源；
3. 托管归属：**原生C侧**；
4. FFI标准方案（纳入你的架构强制规范）
    C裸指针 → FFI桥封装为 HaoLang GC对象 `NativeHandle`
    - `NativeHandle` 属于HaoLang GC对象；
    - handle内部私有保存raw裸指针；上层业务代码看不到裸指针；
    - 绑定Finalizer：GC回收handle时，自动调用C释放接口；
    - 所有资源操作方法封装在handle内部，内部穿过FFI调用C；
5. 所有权规则：
    资源本体仍然属于C；HaoLang通过句柄**代理管理生命周期**，不接管内存分配器。

### 类别4：跨边界共享缓冲区（极少场景，尽量规避）
能拷贝优先拷贝；非要共享：
1. 不能使用HaoLang GC堆内存；
2. 在C侧malloc分配缓冲区；封装为NativeHandle交给HaoLang持有；
3. 禁止GC堆内存对外共享。

## 3 ABI分层实施方法论（落地步骤）
### Step1：区分「内部ABI」与「外部ABI」
1. **HaoLang内部ABI**
编译器内部函数调用、GC对象布局、栈布局。
自由度最高，可以优先适配语言GC模型，不必完全迁就C。
2. **外部FFI ABI**
语言 ↔ C交互边界。**强制对齐平台C ABI**，降低调用桩实现成本。

> 重要：不要为了内部方便，强行让所有内部对象布局完全贴合C；内部优先GC安全，边界靠桥接层转换。

### Step2：边界隔离原则（ABI与托管联动）
所有跨FFI边界的数据流转只有两种合法模式
1. **拷贝语义（首选）**
内存有两份副本，两边各自管理自己内存；
优点：无GC冲突、生命周期互不干扰；
适用：字符串、数组、小型结构体。
2. **句柄代理语义（长期资源）**
不拷贝资源本体；HaoLang持有GC句柄，间接操作C原生资源；
适用：文件句柄、网络连接、第三方库实例。

❌ 禁止模式：直接传递GC对象内部裸指针给C长期持有。

### Step3：结构体ABI设计策略
1. 仅FFI对外使用的结构体：布局严格对齐C ABI（对齐、填充、字段顺序）
2. HaoLang内部业务GC结构体：优先满足GC遍历、写屏障需求，**不必兼容C ABI**；
如需传给C，桥接层做序列化/内存拷贝转换。

## 4 权责速查表（可直接放进架构文档）
| 数据实例 | 内存位置 | 托管方 | FFI ABI策略 |
|---|---|---|---|
| i32/f64 基础值 | HaoLang栈 | HaoLang运行时 | 直接拷贝，布局兼容C ABI |
| String / Array | HaoLang GC堆 | HaoLang GC | 边界拷贝；禁止导出内部指针 |
| HaoLang GC结构体 | HaoLang GC堆 | HaoLang GC | 内部布局自由；跨FFI拷贝转换 |
| FILE*,malloc内存 | C堆/内核 | C运行时 | 封装NativeHandle，代理管控 |

## 5 高频误区汇总
1. 误区：布局兼容C ABI → 内存属于C运行时
纠正：ABI只是数据格式协议，托管权看内存在哪分配。
2. 误区：为了FFI方便，把所有内部对象设计成C兼容布局
纠正：牺牲GC安全性得不偿失，边界用拷贝/转换隔离。
3. 误区：C拿到GC对象指针短期用一下没事
纠正：GC安全点、堆压缩随时移动对象，极易产生野指针崩溃。
4. 误区：NativeHandle接管原生内存所有权
纠正：Handle只是代理释放；内存分配仍然由C运行时负责。

## 6 可直接写入文档的总结金句
ABI定义二进制互通标准，**不改变内存所有权**；
栈基础值直接拷贝互通；
HaoLang GC对象边界优先拷贝隔离；
C原生资源统一封装GC托管句柄做代理管理；
分配方永久持有内存托管权责，跨语言不随意转移所有权。
