# RFC-0005：数组统一基类与强制 `new` 创建

| 字段 | 值 |
|------|-----|
| 状态 | **Implemented** |
| 版本锚点 | v0.60.3 |
| 对标 | C# `Array` 基类 + `new T[]` / `new T[]{…}`；Java 堆数组对象 |

## 1. 动机

`[T]` 已是堆上 GC 数组，但类型系统缺少统一基类 `Array`，且裸 `[1,2,3]` 构造与「对象须 `new`」口径分裂。本 RFC 钉死：`[T] <: Array <: Object`；**语法上数组实例必须经 `new` 创建**。

## 2. 语法规范

### 2.1 类型与成员

- 类型写法仍为 `[T]`；统一基类名 `Array`（builtin / `object.Array`）。
- 成员（`[T]` 与 `Array` 均可）：只读 `length`、`capacity`；`clone()`。
- **索引 / `+=` / `pop` 仅 `[T]`**；在 `Array` 上编译拒绝。

### 2.2 合法创建（仅此）

```hao
new [Int](n)
new [Int](n, fill)
new [Int] { 1, 2, 3 }
new [Int] {}
new [Int] { ...a, ...b }
```

### 2.3 非法

```hao
[1, 2, 3]
[]
var xs: [Int] = []
new [Int]()          // 无长度无初始化器
new Array            // 不可直接 new 基类
```

类型 `[T]`、下标 `a[i]` 不是创建，合法。

## 3. 编译转换

1. `new [T](n[, fill])` → 既有 `@hao_array_new` + 填充。
2. `new [T]{ elems }` → 与昔日裸字面量同一分配/写槽路径，但仅此入口。
3. 裸 `arrayLiteral` primary：**编译错误**（不设兼容期）。
4. ABI 不改：`GC_KIND_ARRAY`；`Array` 为类型系统基类，不改槽布局。
5. `[T] → Array → Object`：`isAssignable`；`is`/`as Array` 认数组指针；合成 `Array.Class`。

## 4. 语义约束

| 规则 | 口径 |
|------|------|
| length | 由创建形态决定；无魔法默认长度 |
| `new [T]{}` | length=0；capacity 可读（实现可 ≥1） |
| clone | `[T].clone()` → `[T]`；`Array.clone()` → `Array`（浅拷贝新实例） |
| 协变 | `[Derived]` 不可赋给 `[Base]`；`[T]` 可赋给 `Array`/`Object` |
| 栈数组 | 不做 |
| 多维 | 不做 |

`collections.Arrays` 保持泛型 `[T]`，不改为丢元素类型的 `Array` 形参。

## 5. 示例

### 5.1 正例

```hao
val a = new [Int]{ 1, 2, 3 };
Array arr = a;
fmt.println(arr.length);
fmt.println(arr.capacity);
val b = a.clone();
```

### 5.2 反例

```hao
// val x = [1, 2];
// arr[0] = 1;          // arr: Array
// var ys: [Object] = new [String]{ "a" };
```

## 6. 歧义分析

| 概念 | 决策 |
|------|------|
| 裸 `[…]` vs `new [T]{…}` | 仅后者构造数组 |
| `{…}` 无 `new` | 仍是 lambda / 块，不是数组 |
| `T...` 隐式 new | 见 RFC-0006，唯一允许的调用方省略 |
| Java 无统一 Array 基类 | Hao 走 C# 路线 |
