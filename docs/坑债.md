## 一、踩坑表（现象 → 原因 → 解法）


> **批末必补**。检索：先看**最近字母节**（当前至 **DR**），再按主题。字母大致按时序：**A～N** 早期 → … → **Z** = v0.29 历史标签（不是「全文最新」）→ **BI～DR** 为 v0.50+ GC/根纪律。新增坑追加到对应节末。

### A. 工具链类

| 坑 | 现象 | 解决 |
|----|------|------|
| MinGW 没有 std::mutex | ANTLR runtime 编译失败 | 换 clang++ + MSVC STL |
| UCRT 的 sprintf 是 inline | `undefined symbol: sprintf` | 在运行时封装层（`stdlib/runtime_*.c`）调用 |
| cmd.exe 不认正斜杠路径 | `hao run` 无输出但退出 0 | 路径转反斜杠，相对路径加 `.\` |
| 便携版缺 lld-link | `program not executable` | clang 和 lld 必须一起拷 |
| 交叉编译缺 libc | `cannot open Scrt1.o` | LLVM 不含任何平台 C 库，必须准备 sysroot |
| 无 SDK 机器链接失败 / `ws2_32.lib` 找不到 / arm vs x64 machine type conflict | 旧 runtime `#pragma comment(lib,"ws2_32")` | **已修（v0.21.0）**：动态加载 `ws2_32.dll`（5.12 / 规则 10） |
| 无 VS 机器 `could not open kernel32.lib/libvcruntime.lib/libucrt.lib` | libcmt DEFAULTLIB；clang 找不到 VS 库路径 | **v0.21.1**：`lib/sysroot/win-<arch>/lib` CRT 最小集 + `DriverLink -L`（与系统 API dynload 分层） |
| PS5.1 跑 `.ps1` 变量名消失 / 中文乱码 | 无 BOM 的 UTF-8 被当系统 ANSI 读，`$变量` 被吃掉 | 含中文的 `.ps1` 存 **UTF-8 with BOM**（`script/win/fetch_winlibs.ps1` / `package.ps1`） |
| musl 缺 crtbeginT.o/libgcc | 链接失败 | 从 musl 工具链 `lib/gcc/<arch>/<ver>/` 拷入 sysroot/lib |
| test.sh 增量"全绿"但 `--rebuild-all` 有 BUILD_FAIL | 增量只查（源/编译器/libhaort.a/VERSION）mtime，不查 stdlib .hao；Windows mtime 粒度可能掩盖 | 改 stdlib/语法后必须 `--rebuild-all` 或手动跑受影响测试，别信增量汇总（v0.17.0 教训） |
| test.sh 在 35 次连续重 build 后报 `local pids=()` 语法错误 | MSYS2 连续 spawn 重进程后 fork 损坏，bash 误报；脚本本身 `bash -n` 通过 | 新 test.sh 只 build 一次套件已规避；旧并行 runner 遇此改用 `--rebuild-all` 前先清 cache 或直接 build 单文件验证 |
| VSCode 插件找 `hao` | 状态栏「未找到 hao」 | 设 `haolang.executablePath` 或保证工作区有 `output/hao.exe` / PATH |

### B. SSA / IR 生成类

| 坑 | 解决 |
|----|------|
| SSA 命名/数字寄存器编号冲突 | 命名与数字寄存器用独立计数器 |
| 一个基本块两条 br | else 后置 `blockTerminated_ = true` |
| `%N` 寄存器编号倒退 | 先发射前驱指令再取返回寄存器，编号与发射顺序一致 |
| `body_.str(saved)` 恢复后写指针回起点覆盖主函数体 | 恢复后 `seekp(0, ios::end)` |
| `fieldPtr()` 内部 nextTemp 导致编号倒退 | 先 fieldPtr（先发射 getelementptr）再取 load 目标寄存器 |
| 常量字符串长度算错 | 长度=字节数+1（`\XX` 占 1 字节） |
| ANTLR 标签替代 `# name` 报 missing RPAREN at '#' | 可选子规则 `(...)?` 内嵌标签不被支持 | 拆独立规则 `classBase` + 顶层标签，`dynamic_cast` 到子类分流（v0.17.0） |

### C. 类型 / 泛型类

| 坑 | 解决 |
|----|------|
| `get`/`set` 无法作方法名 | 定为上下文关键字（语法层收 IDENT） |
| 多接口 `b.g()` 调到 `f()` | 全局槽位编号 |
| 继承虚表全 null | 槽位 key 取**最初声明类**（不用 ownerClass） |
| 抽象方法不能直接调用 | 有虚表槽位就走虚表分派 |
| 泛型实例名 `Box$Int` 变 `Box$` | `monoName` 对基本类型返回固定名 |
| 泛型函数调用 `@id` 未定义 | 用 `sym->irName`（可能是 `first$Int`） |
| 泛型函数体 T 未定义 | 实例化前先设 `currentTypeParams_` |
| 第二次调用泛型函数类型错 | 实例名带类型后缀，每次重算 instName；模板符号不被实例覆盖 |
| 泛型函数体被当普通函数生成 | `if (fn->typeParams()) continue;` |
| 泛型方法把 T/R 当未定义类名 | `currentTypeParams_` 同时含类级+方法级 typeParams 名 |
| 泛型方法 `new List<R>()` 报"未定义泛型类" | 解析签名/生成方法体时 `currentPkgPrefix_` 切到模板所属包 |
| 泛型方法 `X!!.field = v` 报"不是可赋值变量" | 先 `val slot = X!!; slot.field = v;` |
| 数组元素类型不能统一 | 推断公共父类型（基类优先，其次接口） |
| 空数组 `[]` 无法用于 `[String]` | `genVarDecl` 检测空数组字面量，按标注元素类型 `genEmptyArray` |
| `this.items = []` 报"[Int] 不能赋给 [String] 字段" | genAssign 字段/变量赋值时检测空数组字面量按目标类型生成 |
| `isEmptyArrayLiteral` 永远 false | 参数改 `ParseTree*` + DFS 查找（赋值右值是 AssignExprContext，不派生自 Expr） |
| 函数名当表达式报"不是变量" | 函数名返回无 IR 占位，由后续 `(args)` 处理 |
| 链式调用 `a.b[0].c()` 失败 | 重写为逐个后缀归约循环（applyMemberAccess/applyIndex/applyMethodCall） |
| 泛型接口 `interface Iterable<T>` 报"当前版本尚不支持泛型接口" | 编译器不支持泛型接口继承/实例化 | for...in 迭代协议改用 `toArray()` duck-typing（genFor 调 `toArray():[T]` 复用数组快路径），避免泛型接口 |
| `for (x in 非数组)` 报"需要遍历数组" | genFor 只认数组 | 给该类型加 `public toArray():[T]` 方法即被迭代协议识别（v0.15.0） |
| 裸名 `Object` 报"未定义"尽管已 `import object;` | 限定导入不提供裸名；注入判断只查 importPath 命中就跳过 | 通配注入判断改为「已存在 object 通配导入」才跳过；用户写限定 `import object;` 也要补 `object.*`（v0.16.0） |
| 类 override `equals` 报"签名与 Object 不一致" | 类默认继承 Object 后，`equals(o:Object)` 与旧 `equals(o:Hashable)` 签名冲突 | 改用 Object 协议：覆写 `equals(o:Object)`，删掉 Hashable（v0.16.0） |
| `[Circle,Rect,Square]` 多态数组元素类型变 Object 而非 Shape | Object 是通用根，findCommonSupertype 基类循环总先命中它，遮住共同接口 | 基类循环 `continue` 跳过 `object$Object`，让接口有机会命中（真正公共基类如 Animal 仍优先）（v0.17.0） |
| 类名访问实例成员报"静态上下文不能访问" | `ClassName.field`/`ClassName.m()` 时 base.ir 为空（类名无实例） | applyMemberAccess/applyMethodCall 里 `base.ir.empty()` 报错，static 成员走静态分支（v0.17.0） |
| 静态字段非常量初始化报错 | 初版只支持编译期常量 | `emitStaticFieldGlobals` 对非常量改零值全局 + 合成进静态构造器（v0.17.0） |
| 静态构造器体内访问同类静态成员无限递归 | ensureInit 里 guard 未先置位就调 staticinit | guard 三态（0未开始/1进行中/2完成），调 staticinit 前置 1（v0.17.0） |
| enum 常量 `RED, GREEN` 报 extraneous ',' | 初版 `enumConstant*` 不允许逗号 | 改 `(IDENT (COMMA IDENT)*)?`（v0.17.0） |
| `class X extends A, B` 报 mismatched input ',' | extends 只接一个基类，接口必须走 implements | `class X extends A implements B`（旧 `:` 语法允许逗号混列，extends/implements 不行） |
| 继承抽象类报"必须实现继承的抽象方法" | 抽象类 abstract 方法子类未实现且自身非 abstract | 子类加 `override func ...` 或声明 abstract |
| 多文件同包 `class Box/Person` `func add` 重复定义 | 旧单文件用例同名，合并进一个 package main 碰撞 | 重写用例时类/函数名加模块前缀去冲突 |
| `String.length` 对中文 | **码点数**（v0.27）；旧文档写字节数已废 | 要字节数用 `byteLength()` / `getBytes()` |
| 泛型实例 ctor 按未偏移槽位写字段覆盖虚表指针 → 段错误 | 字段槽位偏移（+1 留给虚表）原在 resolveInterfaceImpls，重排后被移到代码生成之后 | 非泛型类在 assignVtableSlots、泛型实例在 instantiateClass 末尾先 `vtableShiftFields`（须在 genConstructor 前）（v0.18.0） |
| is/as 报"没有任何可实例化的类型满足它" | genUnitTopLevel 的 is/as 检查读 typeIdLists_，而 emitTypeIdLists 被移到代码生成后 | emitTypeIdLists 在 genUnitTopLevel 前跑第 1 遍，泛型实例后跑第 2 遍（加 typeIdLists_.count 幂等守卫）（v0.18.0） |
| 实例化接口其方法签名引用的泛型接口未实例化（`Iterator<Int>` 未定义） | ensureInterfaceInstances 在 `std::move(im)` 之后调用，move 后 returnType 已空 | 连带实例化须在 push 之前调用（v0.18.0） |
| 泛型接口裸名匹配失败（`It.iterator()` 查 Iterable$Int 未定义） | isAssignable/applyMethodCall/findCommonSupertype 用 className 裸名，未带 typeArgs | 改按 `makeInterface(name,args)->monoName()` 实例名（v0.18.0） |
| `func main(): Int` 链接报 `value doesn't match function result type 'i32'` | 预存 bug：main 函数头声明为 i32（Bool），但 return 发 i64（Int） | **已修**（v0.19.0）：genReturn/emitUnwindRet 在 inMain_ 且返回 Int 时 trunc i64→i32 再 ret；main 返回类型限 Unit 或 Int |
| 反射 getClass 返回别的类（`typeOf(new Person())` 得 Info） | 两个类虚表内容相同（都仅 Object 方法+null），`private constant` 被链接器合并成同一地址，getClass 按虚表反查误判 | vtable 数组末尾追加 `ptr @<cls>.meta` 反射哨兵使每类虚表内容唯一（v0.19.0）；顺带修 is/as 潜在同类隐患 |
| `Int?` 变量存数值后 C 侧读不到 | `Int?` 是**装箱块指针**（块内容存 i64），不是 i64 值本身；extern 参数/返回值类型不匹配 | 数值用 `Int`（i64）；跨 C 传指针用 `Int?`（块指针原样传递，不拆箱） |
| lambda 里 `fmt.println(...)` 报"捕获了未定义变量 'fmt'" | collectFreeNames 把隐式预导入的包名 fmt／import 别名当自由变量要捕获 | 加 isPkg 检查：包名（fmt/import 别名/全局函数类）不捕获（v0.19.0） |
| 多线程 worker 运行分配代码段错误 | 线程闭包 env 提交后主线程栈不再引用，GC 回收；且保守扫描只扫当前线程栈，worker 内分配对象被其他线程 GC 误回收 | **已根治（v0.20.0 GC v2）**：stop-the-world + 线程注册表 + 扫所有线程栈，worker 内可自由分配。env 仍注册为 GC 根保活（提交后主线程不再引用） |
| 反射 invoke thunk 内联 `getelementptr` 报 "invalid use of function-local name" | 内联 gep 引用函数局部变量 `%argslots`，不能作 constantexpr | 先把 gep 当独立指令发射（`%sN = getelementptr ...`）再 load |
| 反射 invoke 静态方法返回 0 | 静态方法存 `ClassInfo.staticMethods`，emitClassMeta 只遍历 `ci->methods`，静态方法不在元数据 | emitClassMeta 方法数组改为实例方法 + 静态方法都遍历（v0.20.0） |
| Linux 交叉编译 runtime_gc.c 报 `pthread_getattr_np` 未声明 | 需要 `_GNU_SOURCE` | runtime_gc.c 顶部 `#define _GNU_SOURCE`（GC v2 取线程栈顶） |

### D. 异常类

| 坑 | 解决 |
|----|------|
| 异常跨函数传播段错误 | setjmp 必须在用户函数自身栈帧里 IR 直接 call |
| Windows 单参 `@setjmp` 崩溃 | Windows 双参 `_setjmp(buf, frameaddress)`，Linux 单参；都标 returns_twice |
| 嵌套 try 外层重抛已捕获 | catch 体入口先 `store i32 0` 复位 reason |
| 多个并列 try 标签重名 | 用函数内单调递增的 `tryCounter_` |
| 独立类无法被 catch | 所有类都生成虚表 |
| `try{return}` 误报"缺少 return" | genTry 跟踪是否都不落入 cleanup，是则标 unreachable + blockTerminated |
| cleanup 弹帧重复/遗漏 | 帧带唯一 id，`hao_try_end(id)` 只在栈顶匹配时弹，幂等 |

### E. GC 类

| 坑 | 解决 |
|----|------|
| 大量分配后泄漏/崩溃 | 实现保守式标记-清扫，统一走 gc_alloc |
| 寄存器里的活指针扫不到 | x86-64 naked 垫片压栈所有通用寄存器再调 GC |
| naked 垫片破坏调用者状态 | 返回前恢复 rbx/rbp/rsi/rdi/r12-r15，预留 32 字节 shadow space，栈 16 对齐 |
| 数组扩容不能 realloc | gc_alloc 新块 + memcpy，旧块 GC 回收 |
| GC 递归标记深层对象图栈溢出 | 迭代式工作集（动态数组） |
| GCBlock 头 24 字节致用户数据不对齐 | 头部填充到 32 字节 |
| `gc_stack_top` 为 0 | gc_alloc 首次惰性 `gc_init`；Windows 用 `NtCurrentTeb()` |
| `-O0` 用户程序 GC 崩溃 | 用户程序默认 `-O2` |
| GC 标记 O(n²) 慢 | 维护堆地址范围 `[lo,hi]` 快速排除非堆值 |

### F. Lambda / 闭包类

| 坑 | 解决 |
|----|------|
| lambda 引用外层参数报 `undefined value '%n.addr'` | 自由变量分析 `declared` 只放 lambda 自己的形参 |
| 嵌套 lambda 报"未经过自由变量分析" | 对 lambda 的各条语句调 analyzeLambdas，而非 lambda 节点本身 |
| `map<T,R>` 的 lambda 报"返回 Int 与 R 不匹配" | 两遍实参求值：未解析的 R 置空作期望类型，让 lambda 自推返回类型再合一绑定 R |
| lambda 需要忽略实参时引入隐式 it | 无参列表且体里引用 `it` 时自动引入 | 

### G. 链接 / 外部库 / 系统库类

| 坑 | 解决 |
|----|------|
| 拆分 runtime 后 Windows 中文乱码 | 控制台 UTF-8 初始化放进 `runtime_print.c`（有导出符号必链入），别独立成无导出模块 |
| Windows `-lws2_32` 找不到库 | Windows `-l` 找 `<name>.lib`；用 `llvm-lib /OUT:x.lib x.obj` 编 .lib |
| cwd 与源码目录相同时命令重复 `-L` | 生成默认路径后 `std::find` 去重 |
| `@link("foo.c")` 文件/库名不分 | `isLibraryPath`：含分隔符或以 `.lib/.a/.o/.c/.obj/.cpp/.dll` 结尾→文件，否则库名 `-l` |
| os.getenv 返回悬垂/乱码 | getenv 静态缓冲必须 gc_alloc + 拷贝 |
| sync 自旋锁死循环 | `__atomic_compare_exchange_n` 的 expected 就地更新，每次失败重置回 0 |
| winsock.h 与 winsock2.h 类型重定义 | `windows.h` 默认含旧 `winsock.h` | winsock2.h 先于 windows.h 包含，并定义 `WIN32_LEAN_AND_MEAN` |
| net 包内 `accept(client: net.Socket)` 类型不符 | 同包内限定名解析成 `net$Socket` | 同包引用直接用无前缀类名 `Socket` |

### H. extern / 重载类

| 坑 | 解决 |
|----|------|
| extern 函数 `invalid redefinition of function` | `IREmitter::isRuntimeDeclared` 与内建声明去重，命中跳过 declare |
| extern/普通函数缺函数体未拦截 | collectFunctionSignatures 校验：extern 不能有 block，非 extern 必须有 block |
| 函数重载 `invalid redefinition of function @f` | 重载 IR 名带签名后缀（`overloadSuffix`） |
| 重载的第二个函数报"未定义参数 X" | `genFunction` 按 AST 签名从 `overloads_` 匹配选出对应符号 |
| `list.filter({ it % 2 == 0 })` 无法推断 it | `applyMethodCall` 类/接口方法分支求值实参时压入形参类型作期望类型 |

### I. 包 / 多文件类

| 坑 | 解决 |
|----|------|
| 显式文件入口扫目录致多个 main 冲突 | 传文件=只编译列出的文件；传目录=编译该包全部 |
| 跨包限定名调用报"未定义标识符 pkg"二次错误 | alias 是已导入包但成员解析失败时直接返回；每个包建 `pkgExports_` 空条目 |

| 多个同签名 `func init()` 报 `@init` 重复定义 | genFunction 重载匹配 `sym = oc[0]` 全落第一个 | 每包只允许一个 init()，多则报错（v0.17.0） |

### J. 动态加载 / 零 SDK（v0.21.0）

| 坑 | 现象 | 解决 |
|----|------|------|
| `#pragma comment(lib,"ws2_32")` | 无 SDK 机器链接失败；x64/ARM `.lib` 架构冲突 | 禁止 pragma；`hao_dl_open("ws2_32.dll")` + 函数指针表（规则 10 / 5.12） |
| `#include <winsock2.h>` | 头文件声明会变成对导入库的链接依赖 | 手写 ABI 兼容 typedef/常量；不包含 winsock 头 |
| 含 `windows.h` 拉入旧 `winsock.h` | 与手写类型冲突 | `runtime_net.c` 在 include 前 `#define WIN32_LEAN_AND_MEAN` |
| 依赖 ws2_32 的 `htons`/`htonl` | 又引入 DLL 导出符号 | 自实现 `hao_htons`/`hao_htonl`（当前目标均为小端） |
| `hao_dl_sym` 中途失败 | `g_ws.lib` 非空但部分函数指针为 NULL → 下次崩溃 | fail 路径 `hao_dl_close` + `memset(&g_ws,0)` 整表回滚 |
| 验收是否还有 `.lib` 依赖 | 肉眼难查 | `llvm-readobj --coff-directives runtime_net.obj` 应只有 CRT（如 `libcmt`），无 `ws2_32` |
| `#include <windows.h>` 进公共头 | 几乎每个 `.obj` 带 `uuid.lib` + 大量 `__imp_*` | 公共头禁止 windows.h；WinAPI 走 `hao_win_*`（v0.21.1） |
